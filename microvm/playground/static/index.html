Scale a fleet

Scale-down terminates SUSPENDED members first (they still hold memory quota), then the youngest RUNNING. The job log shows the victims before anything is sent.

Lease a VM one task RunMicrovm with a lease in runHookPayload; the VM heartbeats and completes it itself

clientToken = sha256(kind:token), so a replayed launch returns the same VM. The policy becomes the VM's idle policy (max idle = budget, no auto-resume) and its duration cap (budget + slack). The job log shows the encoded payload and the exact RunMicrovm request before anything is sent. With shards > 1 the plane sizes the fan-out first (FleetManager.plan: memory quota, launch rate, policy ceilings) and logs the plan sentence; a rejected plan, or more shards than the concurrency limit, is refused before anything launches; each shard gets lease id <id>-<i> and, for orchestrator kinds, a token from the token field with {i} replaced; then lease_many launches through the bucket and the job follows the fleet job until every shard is done.
